# YesIHave рядом с masterclass

Целевой сервер masterclass: `root@13.143.175.200`. Каталог YesIHave:
`/opt/yesihave`, отдельный Compose-проект `yesihave`. Перед запуском нужно
проверить свободную память, место, порты 8082/443 и текущие контейнеры. Файл
`compose.vds.yml` не занимает порт 80, который использует masterclass.
Дополнение `compose.vds.public.yml` подключает только web-шлюз к общей сети
`edge`. Публичный порт 443 принадлежит самостоятельному роутеру в `/opt/edge`,
а не проекту YesIHave. Его конфигурация и порядок подключения новых сервисов
описаны в [infra/edge/README.md](infra/edge/README.md).

## Подготовка

Соберите JAR локально командой `mvn package`. Соберите Linux-бинарники
хранилища командой `bash scripts/build-storage-binaries.sh` (нужен Go 1.24+
и Git). Перенесите JAR из `target/`, каталог `storage-binaries/`,
`Dockerfile.vds`, `Dockerfile.storage`, соответствующие `.dockerignore`,
оба Compose-файла, nginx-конфигурацию и модель `models/clip-vitb32.onnx` в
`/opt/yesihave`, сохраняя пути.
Создайте `.env.vds` по `.env.vds.example` с отдельными случайными паролями
PostgreSQL и MinIO; права файла — 600. Значения `REPLACE_*` являются
заглушками. Создайте `nginx/htpasswd` с BCrypt-паролем для пользователя
`admin`; этот файл и `.env.vds` исключены из Git и контекста сборки.
Каталог `infra/edge` отдельно перенесите в `/opt/edge`; создайте там `.env`
из `.env.example` с публичным IP. Создайте общую Docker-сеть `edge` по
инструкции роутера до запуска публичного дополнения YesIHave.

Сервер имеет 1 CPU и 2 GB RAM. Приложение ограничено 0.75 CPU и 1280 MB RAM,
Java heap — 384 MB; PostgreSQL и MinIO — по 256 MB. Для пиков загрузки модели
используется swap. Образ собирается из готового JAR без Maven на сервере.
ONNX использует также нативную память вне Java heap.
Нативные библиотеки ONNX извлекаются из JAR при сборке в `/app/onnx-native`
и загружаются через `onnxruntime.native.path` из read-only образа. Каталог
`/tmp` остаётся `noexec`: разрешать исполнение из временного каталога не нужно.

Образы MinIO и mc, указанные в прежнем Docker Compose, недоступны в registry
при проверке 11 октября 2026. VDS использует собственный образ из официальных
исходников [MinIO](https://github.com/minio/minio) и [mc](https://github.com/minio/mc):
commits `7aac2a2c5b7c882e68c1ce017d8256be2feea27f` и
`77f82e18b5401a65958f1619df6ebb994634bd88`. Исходники, проверенные `go.sum`
зависимости и лицензии сохраняются; параметры сборки записаны в
`storage-binaries/provenance.json` и включены в образ.

## Запуск и проверка

На сервере:

```sh
cd /opt/yesihave
docker compose --env-file .env.vds -f compose.vds.yml -f compose.vds.public.yml config --quiet
docker compose --env-file .env.vds -f compose.vds.yml -f compose.vds.public.yml up -d --build --wait --wait-timeout 300
docker compose --env-file .env.vds -f compose.vds.yml -f compose.vds.public.yml ps
docker compose --env-file .env.vds -f compose.vds.yml -f compose.vds.public.yml logs --tail=100 app
cd /opt/edge
docker compose up -d
docker compose logs --tail=50 caddy
curl -u admin https://13.143.175.200/actuator/health
```

Откройте `https://13.143.175.200/` и введите данные Basic Auth. SSH-туннель
не нужен. IP задаётся в `/opt/edge/.env` через `EDGE_PUBLIC_IP`.
Для текущего развёртывания логин и пароль сохранены в локальном
`deployment-access.txt` и `/opt/yesihave/deployment-access.txt` на сервере
(права 600, файл исключён из Git). Не передавайте пароль в URL.
Caddy получает доверенный сертификат Let's Encrypt для IP с профилем
`shortlived` и автоматически продлевает его. Проверка владения IP выполняется
через TLS-ALPN-01 на порту 443; порт 80 не используется. Сертификат действует
около шести дней, поэтому порт 443 должен постоянно оставаться доступным
из интернета. См. [Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)
и [параметры Caddy](https://caddyserver.com/docs/caddyfile/directives/tls).

Пароль, ограничение запросов и защита cross-site запросов остаются в nginx.
Внешний HTTP-порт YesIHave не публикуется; PostgreSQL и MinIO также закрыты.
Запрос `http://13.143.175.200/` по-прежнему открывает masterclass; для YesIHave
важно использовать `https://`. Локальный HTTP-порт 8082 оставлен для диагностики.
Если нужен только закрытый режим, запускайте без `compose.vds.public.yml`;
прямой HTTPS-доступ тогда не создаётся.

## Хранение и обновление

Данные находятся в томах `yesihave_pg_data` и `yesihave_minio_data`.
ACME-аккаунт, сертификаты и ключи принадлежат роутеру и находятся в
`edge_caddy_data`, служебная конфигурация — в `edge_caddy_config`.
Не удаляйте эти тома при обновлении. Обновление/остановка проекта YesIHave
не останавливает общий роутер и другие приложения.
Автозапуск настроен через `restart: unless-stopped`. При обновлении выполните
ту же команду `up -d --build --wait`; перед миграциями сохраните резервные
копии PostgreSQL и MinIO. `down -v` удаляет данные и для обычного обновления
не используется.
Если обновляете только `app` через `up -d --no-deps --wait app`, после
успешного запуска обновите DNS-разрешение backend в nginx:

```sh
cd /opt/yesihave
docker compose --env-file .env.vds -f compose.vds.yml -f compose.vds.public.yml exec -T nginx nginx -t
docker compose --env-file .env.vds -f compose.vds.yml -f compose.vds.public.yml exec -T nginx nginx -s reload
```

Общий edge-роутер для такого обновления перезапускать не нужно.

Модель должна сохранять тот же SHA-256 при неизменной версии embedding.
Замену модели выполняйте через отдельную версию и reindex, описанные в README.

## Личный Telegram-бот — 12 октября 2026

Подключён [@yesihave_bot](https://t.me/yesihave_bot). Бот работает через
long polling; новые входящие порты и маршруты роутера не нужны. Коллекция
общая с веб-интерфейсом. Доступ разрешён только подтверждённому владельцу

`.env.vds` исключены из Git и имеют права 600. Не передавайте токен в
сообщениях, аргументах команд или диагностических выводах. При обновлении
настроек бота сохраняйте существующие пароли PostgreSQL и MinIO.
